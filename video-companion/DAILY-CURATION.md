# Daily video curation interface

The parent task owns ONE daily automation, now authorized by the user, with notifications only when meaningful new reviewed ideas are available. Do not create a second schedule or enable the historical LaunchAgent. Read-only remote inspection on October4 found `world.mingli.video.refresh` disabled and unloaded; its old plist has86400s interval, but the CI workflow is push-only and `refresh.py` only queues candidates. Current approved cadence is daily; task ID/start/timezone belong to the parent-created automation, not this document.

Run identity: `video-curation-YYYYMMDD`, optionally `-N` for a separately reviewed same-day edition. Consult `data/curation-runs.json` before work. No repeated run or unchanged batch should notify or publish.

Editorial scope: new model capabilities, AI video,3D/Blender, industry use, leaders’ views and substantive disagreement. Persistent/cloud agents are a seed, not a permanent topic restriction. Original sources≤7days receive priority; reviewed30day material is the main edition, older sources go to explicit archives. Source dates cannot be refreshed by reviewing/reposting. Never fill a batch with unsupported clip ends. Keep unresolved leads pending, including Oct1 Dots demo until its boundaries are checked.

Discover from official publishers, primary interview/video channels and public metadata without paid APIs. Verify original date/type, speaker/role, primary evidence location, commercial context and a complete30–90second moment retaining important qualifications. Source statements must remain paraphrased and separate from editorial interpretation, conditional outlook and practical experiments. Use the supported official player only; no full footage/transcript downloads, rehosting or synthetic speaker voice.

Prepare a candidate JSON with `cards`, and an independent review receipt with `runId`, `reviewer`, `candidateSha256` (exact candidate bytes), and `reviewedCardIds`. `node scripts/apply-reviewed-batch.mjs CANDIDATE.json REVIEW.json` is a dry run. Add `--apply` only for the reviewed candidate. The updater preserves all previous IDs and never reads or writes private owner profiles. It changes only editorial JSON/curation ledger and is idempotent by run ID and hash. Updating an existing card requires reviewing that full replacement.

Then run `npm test`, `npm run validate`, static private-bundle scan and headless acceptance/real player end checks. Obtain independent actual phone gesture/layout review, preserve current master in the isolated companion branch, and publish through the existing deploy-only CI. No new resources, security grants, credentials, DNS or paid APIs. Verify exact deployed hashes, auth gates, old profile preservation and new clip playback/end before reporting success. Notify only for meaningful newly verified ideas with a brief reason they deserve attention; include opposing views/limits, avoid novelty filler and investment promises. Keep the source/full conversation optional; clip playback is the primary action.
