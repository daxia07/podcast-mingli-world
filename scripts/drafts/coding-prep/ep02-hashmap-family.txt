Cold open. Problem one: given an integer array, return true if any value appears at least twice, else false.

I'll count to eight. Out loud: clarifier, naive Big-O, structure you reach for. One. Two. Three. Four. Five. Six. Seven. Eight.

Model: empty is false. Naive nested compare O of n squared. Better: hash set of seen. If insert collides, true. O of n time, O of n space.

Ritual lock. Restate. Clarify. Naive. Improve. Example by hand. Code while narrating. Edges. Complexity. Mouth first.

Contains Duplicate optimal. Scan left to right. For each value, if it is already in the set, return true. Else add it. After the loop return false.

Tiny walk. Array one, two, three, one. Empty set. See one — store. Two — store. Three — store. One again — already there — true.

Dead-end: sort then check neighbors. That works in O of n log n and uses less memory if you sort in place, but you destroy order and pay the log factor. Under time pressure, say both. Prefer set unless they push space.

Edges: empty false. Single false. All unique false. All same true. Negatives fine in a set.

Speed line for this one. Seen set. Collision means duplicate. O of n time O of n space.

Problem two: Group Anagrams. Given a list of strings, group anagrams together. Anagrams use the same character multiset, different order.

Cold attempt, six seconds. Key idea only. One. Two. Three. Four. Five. Six.

Model: map from a canonical key to a list of strings. Key is sorted characters, or a count tuple of twenty-six letters for lowercase English.

Walk. Input eat, tea, tan, ate, nat, bat.

eat sorts to a e t. Map a e t maps to list eat.
tea sorts to a e t — append tea.
tan sorts to a n t — new list.
ate joins a e t.
nat joins a n t.
bat is a b t alone.

Result groups: eat tea ate. tan nat. bat.

Dead-end: comparing every pair with counters — O of n squared times word length. Say it, then switch to hash map of keys.

Complexity: let n be number of strings, k average length. Sorting keys: O of n k log k. Count keys: O of n k. Space O of n k for the groups.

Problem three: Top K Frequent Elements. Given nums and integer k, return the k most frequent values. Order of output usually free. Frequencies unique in many statements — clarify.

Naive: count with a map, sort pairs by frequency, take top k. Time O of n log n after the count.

Better interview story: frequency map, then bucket sort. Buckets index equals frequency, from zero to n. Place each value into bucket of its count. Scan buckets from high frequency down, collect until you have k.

Walk. nums one, one, one, two, two, three. k equals two.
Counts: one appears three, two appears two, three appears one.
Buckets: index three holds one. Index two holds two. Index one holds three.
Scan from top: take one, take two. Done.

Dead-end: heap of size k is fine too — O of n log k. Say both. Bucket is clean when values are integers and n is the bound.
