Hey. This monologue is only about the second half of the Airwallex coding interview. Twenty five to thirty minutes. Technical deep dive. AI is allowed. They want to see how you use it. Not whether a model can replace you.

Replay this until the prompt templates come out of your mouth without thinking.

Context. You already spent thirty minutes without AI. You should have a working solution, some edges, complexity spoken, and a short list of known gaps. The interviewer will review your code with you. Now you may open Claude Code, Cursor, or Copilot. You use Claude Code. Same project. Same files. Screen still shared. You are still talking to a human.

Mindset. You are the pilot. The model is a powerful intern that hallucinates with confidence. Your job is direction, verification, and taste. Their evaluation list literally includes AI tool use proficiency. It does not include token thrift. Do not optimise for cheapest tokens. Optimise for clear asks, correct code, and explanations you can defend.

Opening the segment. When they signal deep dive, say what you have in thirty seconds. Here is the approach. Here is what works. Here are two gaps I would attack first, tests and this edge. Then open the tool. Narrate that you are enabling AI only now because policy allows it in this segment.

The verify loop. Every single change uses the same five beats.

One. Tell the interviewer the goal of the next change.  
Two. Issue a directed prompt with scope and non goals.  
Three. Read the diff out loud enough that they hear you are not blind accepting.  
Four. Run tests or hand walk an example.  
Five. Accept, edit by hand, or reject with a reason spoken to the interviewer, not to the model drama.

If you skip read and run, you are not piloting. You are gambling.

Prompt templates. Memorise these. Swap in your real names.

Template tests. Add unit tests for empty input, single element, and this domain edge. Do not change production logic unless a test forces a fix. Show me the test file only first if the tool allows that style of scoping.

Template edges list. List edge cases I likely missed for this API. Do not write code yet. I will pick two.

Template complexity. Is my claim O of n time and O of n space accurate? Point to the lines that dominate. Challenge me if I am wrong.

Template one optimise. Suggest one optimisation with trade offs, readability versus speed versus memory. Do not apply it until I say yes.

Template readability. Rename for clarity only. Keep behavior identical. No new dependencies.

Template explain. Explain this function back to me in three sentences as if to a senior reviewer. I will check for mistakes.

Notice what none of these say. None say rewrite the entire solution. None say make it better with no target. None say solve a different LeetCode problem in the background.

Bad first moves. Delete your part one code and regenerate from the prompt. That throws away the signal they already saw and risks code you cannot explain. Accept a multi file rewrite without reading. Argue with the model for five silent minutes. Use AI to hide that you never understood the algorithm. Those fail the craft bar even if the output looks fancy.

Good deep dive arc for twenty five minutes. Minutes zero to three, recap and pick goals with the interviewer. Minutes three to twelve, tests and edges with the verify loop. Minutes twelve to twenty, one optimisation or structure cleanup if happy path is solid. Minutes twenty to twenty five, complexity, remaining risks, how you would productionise. Leave a clean ending. Do not thrash.

When AI is wrong. It will be. Example. It claims linear time while a nested loop remains. You point at the loop. You either fix the claim or fix the code. Example. It introduces a dependency you are not allowed to use. You reject and ask for standard library only. Example. It changes business meaning of an error. You reject and restore the contract. Saying no is seniority.

Talk to the interviewer more than to the tool. The tool is on your screen. The grade is human. Phrase like: I am going to ask it for tests around capacity one. Then after the diff: this test looks right, this one assumes sorted input which we did not, I will drop that. That audio is the product.

How this pairs with practice. After every no AI timed problem this week, spend fifteen to twenty minutes in Claude Code on that same code. Force yourself to use the templates. If you only use AI for greenfield generation at home, you will thrash in the interview. The interview AI segment is improvement under review, not vibes coding a new app.

Culture fit line if they ask how you work with AI day to day. I use agents for boilerplate, tests, exploration, and refactors. I keep design ownership. I run tests. I reject changes I cannot explain. AI generated code meets the same bar as mine. Short. True. Matches what they publish about AI pilots. Especially natural with an ML EM who lives continuous learning with tools. Still verify everything.

Trap clinic.

Trap one. Waiting for the perfect prompt instead of a small verifiable ask. Fix. Smallest prompt that produces a checkable diff.

Trap two. Letting the model drive the conversation. Fix. You propose the next goal to the interviewer first.

Trap three. Polishing names while the happy path is still broken. Fix. Correctness, then tests, then optimise.

Trap four. Shame when you reject AI output. Fix. Rejection with a reason is the skill.

Trap five. Practicing deep dive only in your head. Fix. Real tool, real project, real run.

Closing card. Pilot not passenger. Directed prompt. Read. Run. Decide. Improve your solution. Keep ownership. That is part two.

When you finish this episode, open a recent practice file and run three templates for real. Then listen again tomorrow on a walk. The words should feel as automatic as the eight step ritual.
