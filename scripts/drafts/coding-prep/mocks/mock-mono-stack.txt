[INTERVIEWER] Here is the problem. You are given a list of daily temperatures as integers. For each day, compute how many days you must wait until a warmer temperature appears. If there is no future warmer day, the answer for that day is zero. Return a list of integers the same length as the input. This is the classic daily temperatures pattern, and it is one of the few tagged LeetCode style problems in our ecosystem, so treat it as a real coding bar. What questions do you have?

[CANDIDATE] Restating. Input temperatures index i is the temperature on day i. Output answer i is the smallest positive distance j minus i such that temperatures j is strictly greater than temperatures i, or zero if no such j exists. Clarifying questions. Is the comparison strict greater, not greater or equal? Are temperatures always within a documented range like thirty to one hundred, or arbitrary ints? Can the list be empty? Single pass required or is O of n squared acceptable as a first cut I then improve? May I use O of n extra space? Zero based indices for distance in days, counting the gap in indices?

[INTERVIEWER] Strictly warmer. Temperatures are reasonable ints. Empty input returns empty list. O of n squared as a stated naive approach is fine if you then deliver linear. Extra O of n space is fine. Distance is j minus i in indices. Proceed.

[CANDIDATE] Naive approach. For each day i, scan i plus one to the end until finding a warmer day, record distance or zero. Time O of n squared, space O of one extra besides the answer array. Fine for tiny n, too slow for large series. Improved approach. Monotonic stack of indices of days waiting for a warmer day, kept in decreasing temperature order from bottom to top. Scan left to right. While stack is not empty and today is strictly warmer than the day at stack top, pop that index, set answer at that index to today index minus that index. Then push today index. Days left on the stack at the end never see a warmer day and stay zero if we initialized the answer with zeros. Product framing if this appears in analytics: waiting time until a condition improves, same structure as next greater element. I will hand walk before claiming linear.

[INTERVIEWER] Why store indices on the stack rather than temperatures?

[CANDIDATE] I need both the temperature to compare and the index to write the distance. Index alone lets me read temperature from the array and compute j minus i. Storing only temperature loses the position for the answer write.

[INTERVIEWER] What is the invariant of the stack?

[CANDIDATE] Indices from bottom to top have strictly decreasing temperatures. So the top is the closest previous day that has not yet found a warmer day and is the coldest among unresolved days in the stack sense. When today is warmer, it resolves a suffix of unresolved colder days.

[INTERVIEWER] Full word pseudocode.

[CANDIDATE] Function daily temperatures temperatures. N equals length. Answer equals list of n zeros. Stack empty list of indices. For i from zero to n minus one: while stack not empty and temperatures i is greater than temperatures at stack top: prev equals pop stack. Answer at prev equals i minus prev. Push i onto stack. Return answer. Load bearing: strict greater. Load bearing: store indices. Load bearing: initialize zeros for days that never resolve.

[INTERVIEWER] Why is total time linear if there is a while inside the for?

[CANDIDATE] Each index is pushed at most once and popped at most once. The while runs proportional to pops across the whole algorithm, not n times n. Total push and pop operations O of n, so time O of n. Space O of n for stack and answer in the worst case of strictly decreasing series where nothing pops until the end, and even then answer stays zero.
