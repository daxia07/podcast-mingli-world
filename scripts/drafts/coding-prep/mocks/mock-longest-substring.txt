[INTERVIEWER] Here is the problem. Given a string s, find the length of the longest substring without repeating characters. Substring means contiguous characters. Return the length only.

[CANDIDATE] Restating. Maximum length of a contiguous window where all characters are unique. Clarifying. Empty string? Case sensitive? Unicode? Return length only or the string too? May I use O of alphabet extra space?

[INTERVIEWER] Empty returns zero. Case sensitive. Treat Python characters as units. Length only. O of alphabet or O of n space is fine.

[CANDIDATE] Naive: check all O of n squared substrings with a set per window, or expand from each left until conflict. Improved: sliding window. Move right from zero to n minus one. Maintain left so s left through s right is unique. Use a map from character to last index. When s right was seen at an index greater or equal left, set left to that index plus one. Update last index of s right to right. Track max of right minus left plus one. Alternatively maintain a set and shrink left while conflict. Both are O of n.

[INTERVIEWER] Why is the improved approach worth the extra structure?

[CANDIDATE] Because pure O of n is expected and the window invariant is a core interview pattern that transfers to stream windows and at most k distinct problems. It is still compact to implement.

[CANDIDATE] p w best two. Second w shrinks to w. Then k e builds w k e length three. Final w conflicts and window becomes k e w length three. Best three.

[INTERVIEWER] What is the window invariant in one sentence?

[CANDIDATE] After each step, every character in the closed range left to right appears once, and best stores the max length of any valid window seen so far.

[INTERVIEWER] Describe the API you will implement, then full word pseudocode.

[CANDIDATE] Function length of longest substring s. last empty dict, left zero, best zero. For right, ch in enumerate s: if ch in last and last ch greater or equal left: left equals last ch plus one. last ch equals right. best equals max best and right minus left plus one. Return best. Load bearing: left never decreases. Load bearing: substring not subsequence.

[INTERVIEWER] Technique clinic: derive the sliding window from the definition of substring uniqueness.

[CANDIDATE] A substring is defined by two ends left and right. Uniqueness means no character appears twice inside. If I only increase right, I may introduce a duplicate. Then I must increase left until the duplicate is gone. If I process right in increasing order and always repair left minimally, every right is processed once and left only moves forward, giving linear time. The max over all valid windows is the answer. That derivation prevents memorizing code without understanding.

[INTERVIEWER] Clinic: compare last index map versus frequency map versus set.

[CANDIDATE] Set answers membership: is this char inside the window. Frequency map counts occurrences and supports at most k distinct generalizations. Last index map answers where did this char last appear so I can jump left in one step. For pure no repeats, set or last index both work. I pick last index for jump efficiency and clear code, or set if I want a simple mental model of adding and removing.

[INTERVIEWER] Clinic: prove left never needs to move backward.

[CANDIDATE] Suppose left moved backward. The window would include characters already excluded for a previous right, and uniqueness for a larger right would not require re including them because any window ending at the new right that starts earlier than current left would include the conflict that forced left forward. Formally people use the argument that the minimal valid left is non decreasing in right. In practice I code left equals max of left and candidate which enforces non decrease.

[INTERVIEWER] Clinic hand walk d v d f which answers three.

[CANDIDATE] d best one. v window d v best two. second d: last d at zero, left becomes one, window v d length two. f extends v d f length three. Best three. This catches bugs that clear the entire window to empty on each conflict.

[INTERVIEWER] Clinic: subsequence confusion with an example.

[CANDIDATE] In a b c a, longest unique substring length three a b c. Longest unique subsequence can also pick a b c. In a a a, substring length one, and unique subsequence length one. The algorithms differ more on problems like longest increasing subsequence which is not a window problem. I say contiguous out loud every time.

[INTERVIEWER] Clinic: alphabet optimization.

[CANDIDATE] If characters are lowercase English only, last index array of size twenty six initialized to negative one can replace a hash map. For general Unicode, dict is correct. I implement dict unless constraints scream lowercase.

[INTERVIEWER] Clinic: how you would explain a bug to the interviewer when abba fails.

[CANDIDATE] I say I think left jumped backward because I assigned left to last plus one without checking last is inside the window. I fix with a guard, re-run abba, expect two, continue. Calm debug narration scores points.

[INTERVIEWER] Clinic: streaming version of the problem.

[CANDIDATE] If characters arrive as a stream and I must output the best length so far online, the same window state works: update on each new char and emit best. If I must emit the best substring content, I also store argmax start length. Memory is the window map.

[INTERVIEWER] Clinic: related problem minimum window substring containing all of t.

[CANDIDATE] Harder. Need need counts of required characters and a deficit counter. Expand right to satisfy, shrink left while satisfied, track min length. Same expand shrink skeleton, heavier state. I only open that door if asked.
