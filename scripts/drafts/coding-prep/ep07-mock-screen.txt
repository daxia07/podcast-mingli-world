Problem A. Opens on the shared editor. Given a string of brackets, determine if it is valid. Openers and matching closers, correct order. Types paren square curly.

Cold open. Twelve counts. Full approach out loud. One through twelve.

Model speech you should have said. Restate: validate bracket string. Clarify empty is valid. Only those six characters. Naive wrong stack ideas… Optimal: stack. Scan left to right. On open, push. On close, stack must be non empty and top matches. Pop. End stack empty. Example open paren open square close square close paren — valid. Close first — invalid. Complexity O of n time O of n space. Edges empty, single open, mismatch types, wrong order.

If you froze on the count, that is data. Rewind and re-speak until the stack story is automatic.

Problem B. Harder medium. Given an array of intervals, merge all overlapping intervals. Return merged list sorted by start.

Cold open. Fifteen counts. Approach. One through fifteen.

Model. Clarify: inclusive ends? Integer coords. Mutate okay? Naive: for each pair check overlap — messy. Better: sort by start ascending. Init current as first. For each next: if next start less or equal current end, merge end equals max ends. Else push current, current equals next. Push last. Example one three and two six merge to one six. Then eight ten stays. Complexity O of n log n sort. Edges empty, single, all overlap, touch endpoints if inclusive merge.

What to say when stuck. I see two approaches: A brute O of n squared, B with this structure. Given n up to ten to the five I should take B. If still stuck, ask a leading question they allow: can I assume sorted, is mutating okay.

What never to do. Silent coding for five minutes. Jump to optimal without naive. Invent API without clarifying. Use AI or paste from notes. Apologize more than you think.

Mistake recovery line. Practice saying: I see a bug on the empty case — fixing by returning early. That sounds strong. Silence sounds weak.
